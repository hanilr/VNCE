# Plan: Phase 5 — GPU renderer (`vnce-gpu`)

**Date:** 2026-11-24
**Status:** Approved

## Goal

Render frames on the GPU with `wgpu`, read them back to the CPU as a `Canvas`, and show
them through the existing paths (cell pixel modes and the Kitty / Sixel / iTerm2
protocols). The terminal side does not change. Behind a `gpu` feature flag that is off by
default, so users who do not need the GPU never compile `wgpu`.

Approach (chosen from three): direct `wgpu` access plus two small helpers. A full
high-level renderer (sprites, scenes, cameras) may become its own phase later.

## 1. MSRV

Raise the minimum supported Rust version from 1.85 to 1.87: `wgpu` 30 and all of its
crates (`wgpu-core`, `wgpu-hal`, `wgpu-types`, `naga`) require 1.87.

## 2. Device setup: `Gpu`

- `Gpu::new(GpuOptions)`: a hardware adapter first, then the software fallback adapter
  (WARP on Windows, llvmpipe on Linux), else `GpuError::NoAdapter` so the game can fall
  back to CPU rendering.
- Options: power preference (default high performance), whether software adapters are
  allowed (default yes), backends.
- Environment overrides: `VNCE_GPU_BACKEND` (`vulkan`, `dx12`, `metal`, `gl`) and
  `VNCE_GPU_POWER` (`high`, `low`).
- `gpu.info()`: adapter name, backend, whether it is a software adapter.

## 3. Render target and readback: `RenderTarget`

- Size in pixels, `Rgba8UnormSrgb` texture (shaders write linear colors, the canvas gets
  sRGB values), `resize`.
- `target.view()` for the user's own render passes.
- `target.read_into(&mut canvas)` handles the 256-byte row alignment.
- Readback modes: `Immediate` (default; waits for this frame) and `Pipelined` (two
  buffers, one frame of latency, never stalls the GPU).
- `vnce_term`: `Frame::image_pixel_size(area)` gives the exact pixel size an image needs in
  the current graphics mode, so the GPU renders at the right resolution.

## 4. Helpers

- `ShaderQuad`: the user writes one WGSL function
  `fn shade(uv: vec2<f32>, time: f32, resolution: vec2<f32>) -> vec4<f32>`; the engine adds
  the full-screen triangle and the uniforms.
- `MeshRenderer`: vertices with position and color, indices, a transform matrix, a depth
  buffer and optional 4× MSAA.
- A small own matrix module (perspective, look-at, rotations, scale); no `glam`.

## 5. Facade and demos

- `vnce` gets a `gpu` feature that re-exports `vnce_gpu`.
- No runtime changes: a game keeps a `Gpu` in its state, renders in `render` and calls
  `frame.draw_image`.
- `examples/gpu_shader.rs` (raymarched scene) and `examples/gpu_cube.rs` (spinning cube);
  `G` cycles graphics modes, `--bench` prints render, readback and conversion times.

## Tests

- Without a GPU: row alignment, matrix math, wrapped WGSL validated with `naga`.
- With a GPU: clear and read back, a triangle at a known position. Skipped (not failed)
  when no adapter is available.

## Dependencies (`vnce-gpu` only)

## Risks / notes

- `wgpu` is heavy (compile time, binary size): the feature is off by default.
- Linux servers with neither a GPU nor a software driver cannot use it; a clear error is
  returned, there is no automatic CPU fallback.
- Readback at 1080p is about 8 MB per frame; `Pipelined` exists for that, but writing to
  the terminal will likely be the bottleneck.
- Linux / macOS are checked with `cargo check --target`; running is tested on Windows
  (DX12 and Vulkan) only.

## Implementation notes

- `wgpu` 30 API details: `InstanceDescriptor::new_without_display_handle`, fallible
  `request_adapter`, `PollType::Wait` with a submission index (pipelined readback waits
  only for the previous frame), fallible `get_mapped_range`.
- Device limits are the adapter's own limits, so large targets work where possible;
  target sizes are clamped to `1..=max_texture_dimension_2d`.
- Pixels of cell modes are not square (a quadrant pixel is about 1:2), so
  `Frame::image_pixel_aspect` was added next to `Frame::image_pixel_size`, and
  `ShaderQuad` exposes `globals.pixel_aspect` / `globals.aspect`
  (`ShaderQuad::set_pixel_aspect`). Without it, shapes would be stretched in cell modes.
- The user's WGSL comes before the generated code, so `naga` error line numbers match the
  user's source.
- `MeshRenderer` uses one dynamic-offset uniform per draw; MSAA is lowered to what both
  the color and the depth format support. The MSAA and depth images are discarded after
  each pass.
- The demos start with a cell mode: animating a full-screen Sixel image 60 times per
  second is too slow for most terminals (`G` still cycles through every method).
- Verified on Windows with Vulkan, DX12 and OpenGL (RTX 5070 and Radeon 880M); the WARP
  software adapter was found with `force_fallback_adapter`. Linux and macOS are checked
  with `cargo clippy --target`.
- Measured on the RTX 5070 (render + immediate readback): raymarched scene 0.13 ms at
  400×240 and 1.35 ms at 1920×1080; 10 cubes with 4× MSAA 1.15 ms at 1920×1080.
