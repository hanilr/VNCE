# Plan: Phase 27 — Better mouse support

**Date:** 2026-11-26
**Status:** Planned, waiting for the user's approval to start (the user asked on
2026-11-26 to add better mouse support to the phases)

## Goal

Games built with vnce are often played with the mouse: clicking tiles (Isle), aiming,
dragging, looking around a 3D scene (Glide's photo camera), scrolling lists. Today the
mouse is known only by the cell under it, with three buttons and whole wheel steps, and
every game turns cells into its own picture's pixels by hand. This phase makes the mouse
precise and complete in the native window and in the terminals that allow it.

## What the code has today

- `MouseEvent` carries a column and a row; `InputState` keeps the cell under the mouse,
  three buttons (left, right, middle) and whole scroll steps.
- The window (`vnce-window`) knows the pointer in real pixels but rounds it to the cell;
  pixel (touchpad) scrolling becomes whole steps, and horizontal scrolling is dropped.
- Terminals report cells (`EnableMouseCapture`); the SGR-Pixels mode (DEC 1016) that
  kitty, WezTerm, foot, Ghostty and xterm offer is not used.
- Isle maps the mouse cell to world pixels itself (`update_mouse`); Phase 19 added hit
  testing for widgets, in cells.

## What it adds

1. **Pixel positions:** `MouseEvent` gains the position in pixels of the window or
   terminal when known (the window always; terminals with SGR-Pixels, asked for when
   `mouse_capture` is on and the terminal answers), and `InputState::mouse_pixel()`.
   Without pixels, the middle of the cell is used, so games need no second code path.
2. **Picture coordinates:** a helper that turns the mouse into the pixels of a picture
   drawn with `Frame::draw_image` in an area (`InputState::mouse_in(area, width,
   height)` or a `Frame` method), so Isle's hand-written mapping becomes one call and
   every pixel mode gets sub-cell precision.
3. **More buttons and wheel:** back / forward buttons, horizontal scrolling, smooth
   (fractional) scrolling in the window, and wheel bindings in `ActionMap`
   (`Binding::Wheel`, saved as `mouse:wheelup`), e.g. for zoom.
4. **Clicks and drags:** double clicks (and the click count), drag start, drag delta and
   drag end in `InputState`, so games and widgets need no timers of their own.
5. **Relative motion and pointer lock (window):** `ctx.set_cursor_grab(true)` keeps the
   pointer in the window (or locks it where the system allows) and
   `InputState::mouse_delta()` gives raw motion, for mouse look in 3D games.
6. **Cursor shapes:** `ctx.set_cursor_icon(CursorIcon::Pointer / Text / Crosshair /
   Grab / ...)` in the window (`winit`), and in terminals that support OSC 22 (kitty,
   foot, WezTerm), ignored elsewhere. Mouse enter / leave events for the window.
7. **Widgets and examples:** hover styles and wheel scrolling for `List`, `Table` and
   `Tabs`, dragging for `Slider`, a text cursor shape over `TextInput`; Isle uses the
   picture coordinates, Glide's photo and orbit cameras turn with mouse look, the `ui`
   example shows hover, double clicks and cursor shapes.

## Steps (one commit each)

1. Plan details: the event changes (breaking or not), SGR-Pixels detection, names.
2. Events and input state: pixel positions, more buttons, fractional and horizontal
   scrolling, click counts and drags; `ActionMap` wheel bindings; tests with simulated
   events.
3. Terminals: SGR-Pixels where offered (with a check on the emulated terminals of the
   tests); OSC 22 cursor shapes.
4. The window: pixel positions, all buttons, smooth and horizontal scrolling, enter /
   leave, cursor shapes, pointer grab and raw motion.
5. Picture coordinates helper; Isle and Glide use it and mouse look.
6. Widgets: hover, wheel scrolling, slider dragging; the `ui` example.
7. Docs (tutorial chapter on the mouse, shipping guide), changelog, closing.

## Dependencies

None expected (`winit` already has cursor icons, grabbing and raw device motion).

## Risks / open questions

- Adding fields to `MouseEvent` is a breaking change (the next release after it is a
  minor one); making it `#[non_exhaustive]` with a constructor avoids that later.
- SGR-Pixels support differs by terminal and through tmux; the cell position must stay
  right when a terminal does not answer.
- Pointer lock behaves differently on Windows, macOS, X11 and Wayland (confine versus
  lock); the plan falls back to confining the pointer.
