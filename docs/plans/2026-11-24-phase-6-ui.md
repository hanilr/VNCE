# Plan: Phase 6 — UI widgets (`vnce-ui`)

**Date:** 2026-11-24
**Status:** Approved

## Goal

A small set of widgets for games and graphics applications: only what they need, not a
full TUI framework. Widgets draw into the existing `Buffer`, so they mix freely with
canvases, GPU frames and images in the same frame.

## 1. Design

- Immediate mode: every frame calls `widget.render(area, buffer)`; widgets hold no hidden
  state. All widgets implement the `Widget` trait; widgets that need state (the selected
  row) keep it in a separate state struct (`StatefulWidget`).
- Unicode-aware: wide characters (CJK, emoji) and grapheme clusters are measured and
  wrapped correctly with the existing `unicode-width` / `unicode-segmentation`. No new
  dependencies.
- Styles are patches (as everywhere in the engine), so widgets layer: a block background
  and the text inside it combine.

## 2. Widgets

- **`Layout`:** splits an area horizontally or vertically with constraints (length,
  percentage, ratio, min, max, fill with a weight), spacing and margin. Rounding leftovers
  are distributed deterministically; the result never leaves the area.
  `Rect::centered(width, height)` in `vnce_core` for popups.
- **`Span` / `Line` / `Text` and `Paragraph`:** styled text segments; left / center / right
  alignment; word wrapping (long words are broken); truncation with `…`; vertical scroll.
- **`Block`:** borders on all or selected sides; plain, rounded, double, thick and ASCII
  border sets; titles at the top or bottom with alignment; padding; `block.inner(area)`.
- **`Gauge`:** a progress bar with 1/8-cell precision (`▏▎▍▌▋▊▉█`), an optional label and
  an ASCII mode.
- **`List` / `ListState`:** selectable rows for menus and settings screens: selection,
  scrolling that keeps the selected row visible, a highlight style and symbol,
  `select_next` / `select_previous` helpers.
- **`FpsOverlay`:** FPS, UPS and frame time in a corner, with an optional sparkline
  (`▁▂▃▄▅▆▇█`) of recent frame times. No runtime dependency: the numbers are passed in.
- **`Clear`:** resets an area (under popups).

## 3. Facade and demo

- `vnce` re-exports `vnce_ui`; enabled by default (feature `ui`, no heavy dependencies).
- `examples/ui.rs`: a dashboard with split panes, bordered blocks, animated gauges,
  scrolling wrapped text, a menu (`List`), a live pixel chart inside a block, an FPS
  overlay and a popup (with `Clear`).

## Tests

Widgets render into a `Buffer` and rows are compared as strings: layout rounding and
overflow, wrapping with wide characters, truncation and `…`, border corners, fractional
gauge fills, list scrolling.

## Risks / notes

- Text drawn over Sixel / iTerm2 images is hidden by them (Phase 4 rule), so popups do not
  show above those images; Kitty and cell modes are fine. Documented.
- Box-drawing characters are in every font; the 1/8 blocks are very common. Every widget
  that uses them has an ASCII option anyway.
- Not included: text input and mouse-clickable buttons (possible later).

## Implementation notes

- `List` implements only `StatefulWidget` (not also `Widget`), so `list.render(...)` is
  never ambiguous when both traits are imported.
- Layout: when the area is too small, `Length` / `Percentage` / `Ratio` parts shrink
  proportionally before `Min` parts; free space goes to `Fill` / `Min` / `Max` by weight;
  without growable parts, `Percentage` / `Ratio` rounding leftovers go to the largest
  fractions (`50% + 50%` of 7 is `4 + 3`).
- A title on a side without a border takes a row of its own in `Block::inner`.
- The gauge label is reversed over cells that are at least half filled.
- The FPS overlay does no measuring; the demo keeps the last 24 frame times itself.
- The demo was checked frame by frame on a `TestBackend` (rendered rows printed as text)
  and started on a real Windows console.
