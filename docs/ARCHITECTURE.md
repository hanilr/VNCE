# Architecture

> Status: living document. It records approved design decisions and is updated as the
> project evolves.

## Goal

`vnce` lets developers build graphics, animations and games that run inside a
terminal. Frames can be produced on the **CPU** or on the **GPU**, then converted into
terminal output (styled characters, high-resolution block/braille glyphs, or terminal
graphics protocols where supported).

## Platforms

The engine is **cross-platform** and targets:

- **Windows**: Windows Terminal and the classic console host (conhost).
- **Linux**: common terminal emulators (Kitty, WezTerm, Alacritty, GNOME Terminal, Konsole, xterm, ...).
- **macOS**: Terminal.app, iTerm2, and the emulators above.

| `vnce-raster`     | `vnce_raster`  | Pixel canvas, CPU rasterizer, pixel-to-cell modes.               | Planned |
| `vnce-gpu`        | `vnce_gpu`     | `wgpu` offscreen rendering and readback.                         | Planned |
| `vnce-ui`         | `vnce_ui`      | A small set of widgets for games and graphics applications.      | Planned |
| `vnce` | `vnce`  | Public facade; re-exports the crates above behind feature flags. | Phase 1 |

Package names use the `vnce-` prefix to avoid collisions on crates.io.

## Design decisions

### Terminal layer

- **Escape sequences are generated by our own code** (`vnce_term::ansi`).
- **`crossterm`** is used only for platform-specific work: raw mode, input events,
  terminal size and enabling VT processing on Windows.
- `crossterm` types are **never exposed** in the public API. The engine defines its own
  `Event`, `KeyCode`, `KeyModifiers`, `MouseEvent` types, so the backend can be replaced later.
- The terminal is always restored (raw mode off, main screen, visible cursor), both on
  `Drop` and from a panic hook.

### Rendering model

- **Double buffering**: the previous and current frames are kept as cell buffers; only
  the cells that changed are written to the terminal.
- Each frame is assembled in memory and sent with **a single write**.
- **Synchronized output** (`CSI ? 2026 h/l`) is used where supported, to avoid tearing.
- SGR (style) sequences are emitted only when the style actually changes.
- **Color depth detection** (truecolor / 256 / 16); colors are downsampled to the nearest
  supported color.

### Pixel modes (planned)

| Mode                   | Pixels per cell | Color                          |
| ---------------------- | --------------- | ------------------------------ |
| Half-block `▀`         | 1×2             | Each pixel has its own color   |
| Quadrant               | 2×2             | Two colors per cell            |
| Sextant (Unicode 13)   | 2×3             | Two colors per cell            |
| Octant (Unicode 16)    | 2×4             | Two colors per cell            |
| Braille                | 2×4             | One color per cell             |
| Kitty / Sixel / iTerm2 | Real pixels     | Full color                     |

For two-color modes the best foreground/background pair is chosen per cell. Unsupported
modes fall back automatically to a supported one.

### CPU renderer (planned)

Own rasterizer: lines, rectangles, circles, triangles, sprites, alpha blending.
Optional parallelism may be added later.

### GPU renderer (planned)

`wgpu` (Vulkan / DX12 / Metal). Frames are rendered offscreen, read back to the CPU and
converted through the same pixel modes. Enabled with a `gpu` feature flag.

### Runtime

A game loop with a fixed timestep, frame pacing and input dispatch:

- `Game::update` runs at a fixed rate (1–1000 Hz, default 60); `Game::render` runs at the
  frame limit (`FpsLimit::Fixed(1..=1000)` or `Unlimited`, default 60). Both can be
  changed while the game runs.
- Frames follow the clock, never the input: events are handled while waiting for the next
  frame and cannot trigger extra frames.
- Frame time is clamped to avoid the spiral of death; `render` gets an interpolation
  factor (`alpha`).
- `InputState` tracks held keys. Terminals that report key releases (Windows, or the
  kitty keyboard protocol) give exact releases; elsewhere a timeout is used.
- A `Driver` trait (clock + events) makes runs deterministic in tests (`ScriptedDriver`).

### Widgets (planned)

Only what games and graphics applications need: `Text`/`Label` (Unicode, wrapping,
alignment), `Block` (box-drawing borders, title), `Gauge`, `Layout` (rect splitting) and
an `FpsOverlay` for debugging.

   [`plans/2026-11-24-phase-1-core-and-term.md`](plans/2026-11-24-phase-1-core-and-term.md).
